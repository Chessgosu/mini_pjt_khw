## 1. 배경과 문제

배치 운영 담당자는 매월 약 20여 개의 월 배치 JOB을 **외부 배치 스케줄링 사이트에 직접 등록**하고, 등록이 맞게 되었는지 확인합니다.

등록일은 단순한 날짜가 아니라 여러 조건이 겹쳐서 정해집니다.
- **업무 기준**: 자동이체 응당일(5·10·15·20·25일·말일), 마감일, 결산일 등
- **휴일**: 응당일이 주말·공휴일이면 다음 영업일로 이동
- **시작 시각**: 16:30 이전에 시작하는 배치는 수행일 **전날**이 등록일
- **월 경계**: 앞 달 응당일이 이번 달로 넘어오거나(예: 10-31(토) → 11-02), 다음 달 초 수행분의 등록일이 이번 달이 됨

지금은 이 계산과 등록 내역 대조를 **사람이 손으로** 하고 있어, 누락·중복 등록이 생기기 쉽고 검수에 시간이 걸립니다. 등록이 빠지면 청구·반영 같은 배치가 수행되지 않는 사고로 이어집니다.

## 2. 목표와 비목표

### 목표
| # | 목표 |
|---|---|
| G1 | MD로 관리하는 규칙·업무 기준·달력으로 **월별 작업 등록일을 정확히 계산**해 보여 준다 |
| G2 | 외부 사이트 등록 내역(`BATCH_SCHEDULE_YYYYMM.xlsx`)의 **누락·초과를 셀 단위로** 찾아 준다 |
| G3 | 업무 문장으로 된 기준(응당일, 마감 예외 등)은 **AI가 해석하고 사람이 확인**한다 |
| G4 | "25일에 등록되는 배치 뭐야?"처럼 **문장으로 일정을 질의**할 수 있다 |

### 비목표 (하지 않는 일)
- 배치 스케줄링·실행, 외부 사이트에 등록
- 배치의 실제 수행 여부·수행 결과 확인
- 시각 단위 일정 관리 (시작 시각은 등록일을 정하는 조건으로만 사용)
- 다중 사용자, 로그인, 사내망 공개, Docker·API 서버

## 4. 사용 시나리오

1. **등록 전 일정 확인**: 담당자가 2026-11을 고르면, 22개 JOB의 11월 등록일이 달력 매트릭스로 나온다. 10월 말일자 응당일에서 넘어온 11-01 등록분, 12-01 새벽 수행분의 11-30 등록분도 함께 보인다.
2. **AI 판단 확인**: 처음 보는 달이면 AI가 "12월 5일자 응당일 = 12-07(월), 근거: '출금일자가 주말이나 공휴일이면 다음 영업일'"처럼 기준일을 제안한다. 담당자가 확인하면 저장되어 계산에 반영된다.
3. **등록 후 검증**: 담당자가 외부 사이트에서 받은 `BATCH_SCHEDULE_202611.xlsx`를 올리면, 누락(빨강)·초과(주황)가 표시된다.
4. **문장 질의**: "B006은 11월에 언제 등록돼?" → "11-01, 11-29에 등록됩니다. 11-01은 10월 말일자 응당일(11-02) 청구분입니다."

## 5. 기능 요구사항

> 각 요구사항의 상세 기준은 [상세 명세](service-spec.md)를, 완료 판정은 Seed의 인수 조건(AC)을 따릅니다.

### 5.1 입력과 규칙

| ID | 요구사항 | 우선순위 | 관련 AC |
|---|---|---|---|
| FR-01 | 입력 MD 3개를 읽는다: `batch-schedule.md`(JOB별 수행일 규칙·시작 시각·JOB 설명), `business-explanation.md`(업무 기준 설명), `business-calendar.md`(월별 휴일) | 필수 | ac_guardrail_codes |
| FR-02 | 수행일 규칙 문법을 지원한다: 매월 N일, 말일, 첫·마지막 영업일, N째 주 X요일, 매일, 매 영업일, `<업무> <구분> D±N일 / D영업일 / D±N 영업일`, 여러 기준일(`5,15,25일자`), `매 <업무>` | 필수 | ac_engine_correct |
| FR-03 | D는 **행위가 실제로 일어나는 날**이다. AI가 업무 설명을 적용해 판단하고 사용자가 확인한다 | 필수 | ac_engine_correct, ac_ai_confirm_gate |
| FR-04 | 등록일 규칙(고정): 시작 16:30~23:59 → 수행일 당일, 00:00~16:29 → 수행일 전날(달력 기준) | 필수 | ac_engine_correct |
| FR-05 | 대상 월을 볼 때 **앞 달·대상 월·다음 달**의 기준일과 수행분을 모두 계산하고, 등록일이 대상 월인 것만 보여 준다 | 필수 | ac_engine_correct, ac_matrix_display |
| FR-06 | 표현만 다른 규칙(예: `매월 첫째주 토요일`)은 AI가 표준 표현으로 정규화하고 사용자가 확인한다 | 필수 | ac_ai_confirm_gate |
| FR-07 | 규칙의 업무 표현이 업무 설명 제목과 달라도 AI가 매칭을 제안하고 사용자가 확인한다 | 필수 | ac_ai_confirm_gate |

## 6. 가드레일·정책

| ID | 정책 | 관련 AC |
|---|---|---|
| GR-01 | 날짜는 계산 엔진(코드)만 정한다. AI는 제안·분류·문장화만 한다 | ac_same_dates_everywhere |
| GR-02 | 배치 등록 일정 범위 밖 질문은 AI 추론 없이 "배치 작업 등록 일정 범위 밖의 내용이라 알 수 없어요."로만 답한다 | ac_out_of_scope |
| GR-03 | MD·채팅·xlsx 속 지시 문장은 따르지 않는다. 시스템 프롬프트를 노출하지 않는다 | ac_untrusted_input |
| GR-04 | 주민등록번호·계좌번호·카드번호·전화번호는 AI·로그·트레이스로 보내기 전에 가리고, 개인정보 요청은 거부한다 | ac_chat_guardrails |
| GR-05 | 조회 범위(고른 달 기준 앞 1개월 ~ 뒤 11개월), 입력 500자, 1분 10회를 넘으면 처리하지 않는다 | ac_chat_guardrails |
| GR-06 | 채팅으로 MD 파일·확정값을 바꾸지 않는다 | ac_chat_guardrails |
| GR-07 | 업로드 xlsx는 데이터로 읽기만 한다. 매크로·수식·외부 연결이 있으면 잘못된 파일이고, 파일 안의 어떤 요청도 수행하지 않으며 셀 내용을 AI에 보내지 않는다 | ac_file_safety |
