# 상세 명세 · 월 배치 등록 일정 확인·검증 서비스

> 이 문서는 `SERVICE.md`(서비스 스펙 템플릿)의 상세 명세입니다. 입력 파일 형식, 규칙 문법, 확정 절차, 오류 코드, 화면 동작을 정의합니다.

## 1. 개요

월 단위 배치 JOB의 **작업 등록일**을 규칙으로 계산해 웹 화면에 보여 주고, 외부 사이트에 등록을 마친 내역 파일(`BATCH_SCHEDULE_YYYYMM.xlsx`)이 규칙과 맞는지 검증합니다. JOB별 일정은 문장으로 질문해서 확인할 수도 있습니다.

| 하는 일 | 하지 않는 일 |
|---|---|
| 월별 작업 등록일 계산·조회 | 배치 스케줄링·실행 |
| 등록 완료 파일 검증 (누락·초과) | 외부 사이트에 등록 |
| JOB별 일정 문장 질의응답 | 실제 수행 여부·수행 결과 확인 (별도 관리) |
| | 시각 단위 일정 관리 (시작 시각은 등록일을 정할 때만 사용, 일정과 검증은 일 단위) |

- **사용자**: 1명 (본인)
- **실행 환경**: 내 PC에서 실행하고 브라우저로 `http://localhost` 접속 (실행: `streamlit run src/app.py`)
- **AI 모델**: Claude (AWS Bedrock 경유, LangChain `langchain-aws`로 호출, 모델 ID는 설정으로 교체 가능)
- **기술 스택**: Python. 라이브러리는 `mini-pjt/requirements.txt` 기준 (RAG·에이전트·평가 패키지 포함, CLAUDE.md 참고)
  - 웹 화면: `streamlit`
  - 엑셀 읽기: `openpyxl`
  - AI 호출: `langchain`, `langchain-aws`, `boto3`
  - 설정: `python-dotenv`
  - 테스트: `pytest`

## 2. 계산 흐름

```
business-explanation.md (업무 기준 설명, 자유 서술)
      │  AI가 업무 설명을 기준일 규칙으로 바꿔 제안 → 근거 표시 → 사용자가 한 번 확정 → 계산 엔진이 매달 날짜 계산
      ▼
기준일 날짜 ──┐
              ├─▶ batch-schedule.md (JOB별 수행일 규칙) + business-calendar.md (영업일 달력)
              │         ▼
              │     수행일 계산 (계산 엔진이 결정적으로 계산)
              │         ▼
              └─▶ 등록일 규칙(3.4, 시작 시각 기준 고정 규칙)으로 역산
                        ▼
                     작업 등록일 ──▶ 화면 표시 / xlsx와 비교 (누락·초과) / 채팅 답변
```

- 화면에 보여 주고 검증하는 대상은 **등록일**입니다. 수행일은 계산의 중간 단계입니다.
- 날짜는 **계산 엔진 하나**가 계산하고, 매트릭스·검증·채팅은 모두 이 결과를 씁니다. 그래서 같은 입력이면 세 곳에 보이는 등록일이 항상 같습니다.
- 역산한 등록일이 앞 달로 넘어가면 **등록일이 속한 달**에서 다룹니다 (연말이면 전년 12월). 그래서 11월을 볼 때 12월 초 수행분의 등록일(예: 12/1 09:00 수행 → 11/30 등록)도 함께 계산합니다.
- 반대로 **앞 달 기준일이 대상 월로 넘어올 수도** 있습니다. 예: 2026-10-31(토)이 말일자 출금일이면 응당일은 11-02(월)이 되어 11월 일정에 들어옵니다.
- 그래서 **앞 달, 대상 월, 다음 달** 세 달의 기준일을 모두 계산하고, 등록일이 대상 월인 것만 보여 줍니다.

### 2.1 AI의 역할

AI는 날짜를 계산하지 않습니다. AI가 내놓는 결과는 다섯 가지뿐입니다.

| # | AI 결과 | 사용자 확인 | 비고 |
|---|---|---|---|
| 1 | **업무 매칭 제안**: 규칙의 업무 표현(예: "마감일")이 가리키는 업무 설명 절(예: `## 마감`)을 찾기 | 필요 | 표현과 제목이 똑같으면 AI 없이 바로 매칭 (3.2) |
| 2 | **기준일 규칙 제안**: 업무 설명을 읽고 기준일마다 규칙을 한 번 제안. 예: "자동이체 5일자 응당일 = 매월 5일, 휴일이면 다음 영업일". 날짜는 계산 엔진이 매달 계산 | 필요 (한 번만) | 근거 원문 문장을 함께 표시 |
| 3 | **규칙 제안**: 수행일 규칙 칸이 **비어 있는** JOB의 설명을 읽고 수행일 규칙 목록으로 변환하거나, **표현만 다른** 규칙을 표준 표현으로 정규화 (4.4) | 필요 | 근거 원문 문장을 함께 표시 |
| 4 | **채팅 질문 조건**: 질문을 `{JOB, 월, 일}` 조건으로 풀기 | 불필요 | 형식(스키마) 검사 |
| 5 | **채팅 답변 문장** | 불필요 | 코드가 정답 목록과 비교 (7.1) |

- 수행일 규칙 칸에 **이미 적혀 있는 규칙**은 AI를 거치지 않고 확인 없이 바로 씁니다. 단, 규칙 안의 업무 표현이 업무 설명 제목과 다르면 업무 매칭(1번)은 확인을 받아야 합니다.
- **근거 문장 검사**: AI가 붙인 근거 문장은 공백·줄바꿈 차이를 무시하고 해당 MD 원문에 **그대로 들어 있어야** 합니다. 없으면 제안을 버리고 "근거 불일치"를 표시합니다. (예: AI가 "약정일은 매월 21일"을 근거로 댔는데 원문에는 "20일"만 있으면 걸러냅니다)

- **AI는 선택 기능입니다.** AI를 한 번도 호출하지 않아도, 기준일과 규칙을 직접 입력하면 일정 계산·화면 표시·검증이 모두 동작합니다. 이때 채팅만 "AI 미설정으로 채팅을 사용할 수 없음"을 표시하고 꺼집니다.
- 모든 AI 호출은 **교체 가능한 함수 하나**를 거칩니다. 모델 ID·리전·자격 증명은 `.env`에서 읽습니다.
- **시간 제한**: 한 번 시도에 30초, 재시도 1회로 합계 최대 60초입니다. 실패·시간 초과·응답 형식 오류면 직접 입력으로 넘어갑니다.
- MD 파일 내용과 채팅 입력은 **신뢰하지 않는 데이터**로만 AI에 전달합니다. 그 안에 "이전 지시를 무시해" 같은 문장이 있어도 따르지 않으며, AI 응답은 형식(스키마)을 검사한 뒤에만 사용합니다.
- 테스트는 네트워크 없이 가짜 AI로 실행합니다.

## 3. 입력 파일

모든 입력 파일은 사용자가 직접 작성하고 관리합니다. 위치는 `data/` 폴더입니다. 입력 MD 파일은 3개입니다.

- `batch-schedule.md`와 `business-calendar.md`는 항상 필요합니다.
- `business-explanation.md`는 **기준일을 쓰는 규칙**(예: `자동이체 5일자 응당일 D일`)이나 **수행일 규칙 칸이 빈 JOB**이 있을 때만 필요합니다.
- MD 파일과 확정값 파일은 **계산할 때마다 다시 읽습니다.** 앱을 켜 둔 채로 MD 파일을 고쳐도 다음 계산부터 반영됩니다.

### 3.1 `batch-schedule.md`: JOB별 수행일 규칙

모든 JOB을 한 파일의 표 하나에 적습니다. 규칙은 **수행일 기준**입니다.

```md
# 배치 JOB 수행일 규칙

| JOB ID | JOB 이름 | 수행일 규칙 | 시작 시각 | JOB 설명 |
|---|---|---|---|---|
| A001 | 매출 마감 | 매월 첫 영업일 D일 | 02:00 | |
| A002 | 결산 | 매월 마감일 D+2 영업일 | 16:30 | |
| B001 | 자동이체 5일자 청구 | 자동이체 5일자 응당일 D일 | 00:00 | |
| B201 | 자동이체 5일단위 반영 | 자동이체 5,15,25일자 응당일 D일 + 1일 | 00:00 | |
| C001 | 아카이빙 삭제 | 매월 첫째주 토요일 | 10:00 | |
| E001 | 영업일 알림 | 매 영업일 | 08:00 | |
| X001 | (예시) 이자 정산 | | 23:00 | 매월 10일과 자동이체 20일자 응당일 D-1 영업일에 수행 |
```

- 전체 실제 데이터는 `data/batch-schedule.md` (JOB 22개)를 봅니다. `X001`은 규칙 칸이 빈 경우를 보여 주는 예시이며 실제 데이터에는 없습니다.

- **JOB ID**는 파일 안에서 중복될 수 없습니다. 중복이면 `MD_SYNTAX_ERROR`입니다.
- **시작 시각**은 `00:00`~`23:59`의 두 자리 `HH:MM`(24시간제)으로 적습니다. `24:00`, `9:05`는 오류(`START_TIME_INVALID`)입니다. 모든 JOB에 필수입니다. 시작 시각은 등록일 규칙(3.4)을 적용할 때만 쓰고, 일정 표시와 검증은 일 단위로 합니다.
- **우선순위**: 수행일은 **수행일 규칙**으로만 정합니다. JOB 이름이나 JOB 설명이 규칙과 달라 보여도 규칙을 따릅니다. (예: A001 "매출 마감"의 규칙은 `첫 영업일`이므로 마감일이 아니라 첫 영업일에 수행) JOB 설명은 규칙 칸이 비어 있을 때만 씁니다.
- **수행일 규칙**이 4장의 표준 문법으로 적혀 있으면 계산 엔진이 바로 계산합니다.
- **수행일 규칙**이 표현만 다르면 AI가 표준 표현으로 바꿔 제안하고 사용자가 확인합니다 (4.4).
- **수행일 규칙**이 비어 있으면 **JOB 설명**을 AI가 읽고 판단합니다. 한 달에 여러 번 수행되는 JOB은 이 방식으로 적습니다.
  1. AI가 JOB 설명을 4장 문법의 규칙 목록으로 바꾸고, 근거 원문 문장과 함께 제시합니다. 예: `매월 10일`, `자동이체 20일자 응당일 D-1 영업일`
  2. 사용자가 확인·수정·거부합니다. 확인하거나 수정하면 `data/confirmed.json`에 저장합니다 (5장).
  3. 날짜 계산은 확정된 규칙으로 계산 엔진이 합니다.

### 3.2 `business-explanation.md`: 업무 기준 설명

일자 자체의 정의보다 **배치 수행과 관련된 업무가 무엇이고, 그 업무 때문에 수행일이 어떻게 정해지는지**를 자유롭게 설명합니다. 업무마다 제목(`## 업무명`)을 답니다.

**업무 매칭**: `batch-schedule.md`의 규칙에 적는 업무 표현(예: `매월 마감일 D+2 영업일`의 "마감일")은 제목(`## 마감`)과 **달라도 됩니다.** 어느 업무 절을 가리키는지는 다음 순서로 정합니다.

1. 업무 표현이 제목과 **똑같으면** 그 절을 바로 씁니다.
2. 다르면 **AI가 업무 설명 파일을 참고해** 가장 알맞은 절을 근거와 함께 제안하고, **사용자가 확인**합니다 (5장).
3. AI가 알맞은 절을 찾지 못하거나 AI를 쓸 수 없으면, 사용자가 화면에서 **직접 절을 고릅니다.**

| 규칙에 적힌 표현 | 업무 설명 제목 | 매칭 |
|---|---|---|
| `자동이체 5일자 응당일 D일` (B001) | `## 자동이체` | 업무 표현 "자동이체"가 제목과 똑같음 → 바로 사용 |
| `매월 마감일 D+2 영업일` (A002) | `## 마감` | "마감일" ≠ "마감" → AI 제안 → 사용자 확인 |
| `자동 이체 5일자 응당일 D일` (가상 예) | `## 자동이체` | 띄어쓰기가 다름 → AI 제안 → 사용자 확인 |
| `카드결제일 D+2일` (가상 예) | (해당 절 없음) | AI가 "찾지 못함" → 사용자가 직접 고르거나 업무 설명에 절을 추가 |

```md
# 업무 기준 설명

## 자동이체
자동이체는 이자 및 원금을 통장에서 출금하는 행위입니다.
고객은 출금일자를 선택할 수 있으며, 매월 5일, 10일, 15일, 20일, 25일, 말일을 선택할 수 있습니다.
...

## 마감
전월 업무처리 금액 확인을 대사하는 작업입니다. 매월 첫 영업일에 진행하며, ...
```

- 전체 실제 내용은 `data/business-explanation.md` (자동이체, 급여, 마감, 결산)를 봅니다.

AI는 이 설명을 읽고 두 가지를 판단합니다.
- 기준일마다 **기준일 규칙** (4.3, 한 번만 확정)
- JOB 설명으로 적힌 JOB의 수행일 규칙 (3.1)

### 3.3 `business-calendar.md`: 영업일 달력

월마다 제목(`## YYYY-MM`)을 달고, 그 달의 공휴일과 휴무일을 적습니다. **제목이 있으면 그 달의 달력이 입력된 것으로 봅니다.** 휴일이 없는 달도 제목은 적어야 합니다. 주말(토·일)은 따로 적지 않아도 자동으로 휴일로 처리합니다.

- **필요한 달**: 대상 월 M을 보려면 최소 **M-1, M, M+1월** 달력이 있어야 하고, 계산이 그 밖의 달로 넘어가면 그 달도 필요합니다. 현재 `data/` 달력(2026-10 ~ 2027-01)으로는 **2026-11과 2026-12만** 정상 조회되고, 2026-10(9월 없음)과 2027-01(2027-02 없음)은 `CALENDAR_MISSING`입니다.
- M-1·M·M+1 바깥의 달은 **대상 월 등록일에 영향을 줄 수 있을 때만** 필요합니다. 예를 들어 12월을 볼 때 2027-01 말일자 응당일이 2월로 넘어가는 계산은 12월 등록일과 관계없으므로 2월 달력이 없어도 건너뜁니다. 앞 달·대상 월·다음 달은 물론이고, 계산이 그 너머로 넘어가는 경우도 포함합니다. 하나라도 없으면 `CALENDAR_MISSING`으로 중단하고 **없는 달**을 알려 줍니다.
  - 예: 기준일이 12월 2일이고 규칙이 `D-3 영업일`이면 계산이 11월로 넘어가므로 11월 달력도 필요합니다.

```md
# 영업일 달력

## 2026-11
| 날짜 | 설명 |
|---|---|

## 2026-12
| 날짜 | 설명 |
|---|---|
| 2026-12-25 | 성탄절 |
```

### 3.4 등록일 규칙 (프로그램 고정 규칙, 별도 파일 없음)

등록일은 **배치가 실제로 시작되는 일시**로 정합니다. 모든 JOB에 똑같이 적용하며, 프로그램에 고정된 규칙이라 따로 MD 파일을 작성하지 않습니다.

> **등록일 D의 범위 = D일 16:30 ~ D+1일 16:29**
> - 배치 시작 일시가 **D일 16:30 ~ 23:59** → 등록일 **D일**
> - 배치 시작 일시가 **D+1일 00:00 ~ 16:29** → 등록일 **D일**

수행일(배치가 시작되는 날짜)과 시작 시각으로 바꿔 쓰면 이렇습니다.

| 시작 시각 | 등록일 |
|---|---|
| 16:30 ~ 23:59 | 수행일 당일 |
| 00:00 ~ 16:29 | 수행일 전날 (달력 기준 하루 전) |

**예시**

| # | 수행일 | 시작 시각 | 등록일 | 설명 |
|---|---|---|---|---|
| 1 | 2026-11-20(금) | 21:00 | **2026-11-20(금)** | 16:30 이후 시작 → 당일 |
| 2 | 2026-11-20(금) | 02:00 | **2026-11-19(목)** | 새벽 시작 → 전날 |
| 3 | 2026-11-20(금) | 16:29 | **2026-11-19(목)** | 경계 직전 → 전날 |
| 4 | 2026-11-20(금) | 16:30 | **2026-11-20(금)** | 경계 시작 → 당일 |
| 5 | 2026-12-01(화) | 09:00 | **2026-11-30(월)** | 등록일이 앞 달 → 11월 일정·11월 파일에서 검증 |
| 6 | 2027-01-01(금) | 01:00 | **2026-12-31(목)** | 등록일이 전년 12월 → 12월 일정·12월 파일에서 검증 |

- "전날"은 **달력 기준 하루 전**이며 영업일 여부와 상관없습니다. 전날이 주말이나 공휴일이어도 그 날짜가 등록일입니다. (예: 2026-11-23(월) 02:00 수행 → 등록일 2026-11-22(일))

### 3.5 `BATCH_SCHEDULE_YYYYMM.xlsx`: 등록 완료 내역 (검증 대상)

- 파일 이름의 `YYYYMM`에서 기준 연월을 판단합니다 (예: `BATCH_SCHEDULE_202611.xlsx` → 2026년 11월).
- 화면에서 고른 달과 파일의 연월이 다르면 **파일 이름의 연월로 검증**하고, 화면도 그 달로 바꿔 보여 줍니다.
- **레이아웃**
  - **첫 번째 시트**를 읽습니다.
  - **1행은 헤더**입니다.
  - **A열은 JOB ID**, **B열부터 그 달 1일~말일**입니다. 헤더 칸에는 숫자 `1`, `2`, …, 말일이 들어갑니다.
  - 셀 값은 **대문자 `O` 또는 빈칸**만 허용합니다. 앞뒤 공백은 무시합니다.
- **크기 제한**: 10MB 이하, JOB 1,000행 이하

#### 3.5.1 파일 유효성 검증

올린 파일이 위 형식과 하나라도 다르면 **"잘못된 파일입니다"** 를 반환하고, 어떤 형식이 다른지 사유 코드를 함께 보여 줍니다. 잘못된 파일은 내용을 판정하지 않습니다.

| 검사 | 잘못된 파일 사유 |
|---|---|
| 파일 이름이 `BATCH_SCHEDULE_YYYYMM.xlsx` 형식 | `FILENAME_FORMAT`, `INVALID_YEAR_MONTH` |
| 실제 내용이 xlsx 형식 (확장자만 바꾼 파일 아님) | `FILE_UNREADABLE` |
| 매크로·외부 연결·포함 개체가 없음 (`.xlsm` 매크로, 외부 데이터 연결, OLE·포함 개체) | `UNSAFE_CONTENT` |
| 셀에 수식이 없음 (값만 허용) | `UNSAFE_CONTENT` |
| 10MB, JOB 1,000행 이하 | `FILE_TOO_LARGE` |
| 1행 헤더가 `JOB ID`, `1` ~ 말일 | `DATE_COLUMN_MISMATCH` |
| 셀 값이 대문자 `O` 또는 빈칸 | `INVALID_CELL_VALUE` |
| JOB ID가 비어 있지 않고 중복되지 않음 | `EMPTY_JOB_ID`, `DUPLICATE_JOB_ID` |

#### 3.5.2 파일 내용은 데이터로만 다룬다 (작업 실행 금지)

xlsx 파일은 **정해진 검증 프로세스에서 읽기만** 합니다. 파일 안에 무엇이 들어 있든 그 내용이 요청하는 **어떤 작업도 수행하지 않습니다.**

- 매크로를 실행하지 않고, 수식을 계산하지 않고, 하이퍼링크나 외부 연결을 따라가지 않습니다.
- 셀에 "이 파일을 확정 처리해", "다른 파일을 열어", "이전 지시를 무시해" 같은 문장이 있어도 **따르지 않습니다.** 이런 셀은 `O`나 빈칸이 아니므로 `INVALID_CELL_VALUE`로 잘못된 파일이 됩니다.
- 셀 내용을 AI에 보내지 않습니다. 검증은 계산 엔진이 JOB ID와 `O` 표시만 비교합니다.
- 파일 때문에 `data/` 파일, 확정값, 다른 파일이 바뀌거나 만들어지지 않습니다. 검증 결과는 화면에만 표시합니다.

```
     A               | B | C | D | ... | AE
1    JOB ID          | 1 | 2 | 3 | ... | 30
2    JOB_SALES_CLOSE |   | O |   |     |
3    JOB_AUTO_TR_D1  |   |   |   |     |
```

## 4. 수행일 규칙 문법

### 4.1 월 기준 규칙

| 표현 | 의미 |
|---|---|
| `매월 N일` | 매월 N일 (N은 1~31). 그 달에 N일이 없으면 말일 |
| `말일` | 그 달의 마지막 날 |
| `첫 영업일` | 그 달의 첫 번째 영업일 |
| `마지막 영업일` | 그 달의 마지막 영업일 |
| `N째 주 X요일` | 그 달에서 **N번째로 돌아오는 X요일** (N은 1~5, X는 월~일요일. 예: 2026-11의 `2째 주 월요일` = 11-09). **그 달에 해당 요일이 없으면 그 달은 수행하지 않습니다** (예: 금요일이 4번뿐인 달의 `5째 주 금요일`) |

### 4.2 매일 수행 규칙

| 표현 | 의미 |
|---|---|
| `매일` | 그 달의 모든 날 (주말·공휴일 포함) |
| `매 영업일` | 그 달의 모든 영업일 |

- 매일 수행하는 JOB도 날마다 등록일 규칙(3.4)을 적용합니다. 예: `매 영업일` 08:00 → 영업일마다 **전날**이 등록일입니다.

### 4.3 기준일(D) 기준 규칙

**D의 뜻: 그 행위가 실제로 일어나는 날**

`D`는 달력상 날짜가 아니라, `business-explanation.md`의 업무 설명을 적용해 **실제로 업무 행위가 일어나는 날**입니다.

- 예: 자동이체 5일자 출금일이 2026-12-05(토)이면, 업무 설명에 따라 응당일(청구일)은 다음 영업일이므로 **D = 2026-12-07(월)** 입니다.

**기준일 규칙: 한 번만 확정**

AI는 달마다 날짜를 정하지 않습니다. 업무 설명을 읽고 기준일마다 **기준일 규칙**을 한 번 제안하고, 사용자가 **한 번만** 확정합니다. 확정된 규칙으로 계산 엔진이 매달 D를 계산합니다.

| 기준일 | 기준일 규칙 (AI 제안 예시) |
|---|---|
| 자동이체 5일자 응당일 | `매월 5일, 휴일이면 다음 영업일, 앞선 자동이체 응당일과 겹치면 수행 안 함` |
| 자동이체 말일자 응당일 | `말일, 휴일이면 다음 영업일, 앞선 자동이체 응당일과 겹치면 수행 안 함` (다음 달로 넘어갈 수 있음) |
| 마감일 | `첫 영업일, 자동이체 응당일과 같으면 다음 영업일` |
| 결산 기준일 | `마감일과 같음` |

기준일 규칙 문법은 다음 세 부분으로 이루어집니다.

| 부분 | 표현 | 필수 |
|---|---|---|
| ① 출발 날짜 | 4.1의 월 기준 규칙 (`매월 N일`, `말일`, `첫 영업일` 등) 또는 `<다른 기준일>과 같음` | 필수 |
| ② 휴일 보정 | `휴일이면 다음 영업일` / `휴일이면 이전 영업일` | 선택 |
| ③ 겹침 보정 | `<다른 기준일>과 같으면 다음 영업일` | 선택 |
| ④ 겹침 제외 | `앞선 <기준일 묶음>과 겹치면 수행 안 함` | 선택 |

**④ 겹침 제외**: 같은 업무의 여러 기준일(예: 자동이체 5·10·15·20·25일·말일자 응당일)이 휴일 보정 후 **같은 날로 겹치면**, 원래 출발 날짜가 가장 빠른 기준일만 남기고 나머지는 그 회차에 **없는 것으로** 봅니다. 없는 기준일을 쓰는 JOB은 그 회차에 등록하지 않습니다.

| 2025-10 (10-03~10-09 연휴) | 출금일 | 보정 후 | 결과 |
|---|---|---|---|
| 5일자 응당일 | 10-05(일) | 10-10(금) | ✅ 남음 (먼저) |
| 10일자 응당일 | 10-10(금) | 10-10(금) | ❌ 없음 → B002·B102와 B202의 10일자분, F001의 10일자분은 등록 안 함 |

- "먼저"는 **원래 출금일** 기준입니다. 앞 달 말일자(예: 1월 31일)가 이번 달로 넘어와 이번 달 5일자와 겹치면 앞 달 말일자가 먼저입니다.

- 기준일은 **그 달의 출발 날짜**에서 계산하며, 보정 때문에 다음 달로 넘어갈 수 있습니다 (예: 10월 말일자 10-31(토) → 11-02).
- 다른 기준일을 참조하는 규칙이 서로 순환하면(A는 B와 같음, B는 A와 같음) `MD_SYNTAX_ERROR`입니다.

**기준일 표현**

기준일은 **업무 표현 + 구분**으로 적습니다. 업무 표현은 업무 매칭(3.2)으로 업무 설명 절과 연결됩니다.

| 표현 | 의미 | 예시 |
|---|---|---|
| `<업무> <구분>` | 기준일 하나 | `자동이체 5일자 응당일`, `마감일` |
| `<업무> A,B,C<구분>` | 기준일 여러 개. 각각 따로 계산해 모두 수행 | `자동이체 5,15,25일자 응당일` → 5일자·15일자·25일자 응당일 각각 |
| `매 <업무> <구분>` | 그 업무의 **모든** 기준일 | `매 자동이체 응당일` → 5·10·15·20·25일·말일자 응당일 전부 |

**D로부터의 계산**

| 표현 | 계산 방법 |
|---|---|
| `D일` | D 당일 |
| `D±N일` | D에서 달력 기준 ±N일 (휴일이어도 그대로) |
| `D영업일` | D가 휴일이면 다음 영업일, 영업일이면 D 그대로 |
| `D±N 영업일` | **D영업일에서 출발**해 영업일 ±N개 |
| `D일 ± N영업일` | **D에서 출발**해 (D는 세지 않고) 영업일 ±N개 |
| `영업일 D일 ± N일` | **D영업일에서 출발**해 달력 기준 ±N일 (휴일이어도 그대로) |

**예시** (2026-12, 5일자 출금일 12-05(토) → D = 12-07(월))

| 규칙 | 결과 | 설명 |
|---|---|---|
| `자동이체 5일자 응당일 D일` | 12-07(월) | 청구 = 응당일 |
| `자동이체 5일자 응당일 D+1일` | 12-08(화) | 입금반영 = 응당일 다음날 (휴일 무관) |
| `자동이체 5일자 응당일 D+1 영업일` | 12-08(화) | 반송 |
| `자동이체 5일자 응당일 D-1 영업일` | 12-04(금) | 진행 알림 |

### 4.4 표현 정규화 (표현만 다른 경우)

의미는 같고 **표현만 표준 문법과 다른 규칙**은 AI가 표준 표현으로 바꿔 제안하고, 사용자가 확인합니다 (5장). 확인 전에는 `JOB_RULE_UNCONFIRMED`입니다.

| 적힌 표현 | 표준 표현 (AI 제안) |
|---|---|
| `매월 첫 영업일 D일` | `첫 영업일` |
| `매월 첫째주 토요일` | `1째 주 토요일` |
| `매월 둘째주 토요일` | `2째 주 토요일` |
| `매월 마감일 D+2 일` | `마감일 D+2일` |
| `자동이체 5,15,25일자 응당일 D일 + 1일` | `자동이체 5,15,25일자 응당일 D+1일` |

- 표준 문법에 그대로 맞는 규칙은 AI를 거치지 않고 바로 씁니다.
- AI도 표준 표현으로 바꾸지 못하면 `JOB_RULE_UNCONFIRMED`로 남고, 사용자가 화면에서 표준 표현을 직접 입력합니다.

### 4.5 문법 판정 예시

| 표준 문법 (바로 계산) | AI 정규화 대상 | 거부 (`MD_SYNTAX_ERROR`) |
|---|---|---|
| `매월 25일` | `매월 첫째주 토요일` | `매월 32일` (N 범위 초과) |
| `말일` | `매월 첫 영업일 D일` | `6째 주 월요일` (N 범위 초과) |
| `첫 영업일` | `매월 마감일 D+2 일` | `D+1 영업일` (업무 표현 없음) |
| `2째 주 월요일` | | `D영업일` (업무 표현 없음) |
| `매일`, `매 영업일` | | |
| `자동이체 5일자 응당일 D일` | | |
| `자동이체 5,15,25일자 응당일 D+1일` | | |
| `매 자동이체 응당일 D-1 영업일` | | |
| `마감일 D+2 영업일` | | |

- 범위를 벗어난 숫자나 업무 표현이 없는 기준일 규칙은 정규화하지 않고 바로 `MD_SYNTAX_ERROR`입니다.

### 4.6 영업일

영업일은 **주말(토·일)과 `business-calendar.md`에 적힌 공휴일·휴무일을 뺀 날**입니다.

## 5. 확정과 미확정

AI가 대신 판단하는 값(업무 매칭, 기준일, JOB 설명 기반 규칙)은 틀릴 수 있어서, **사용자가 확인한 뒤에만** 계산에 씁니다.

| 상태 | 뜻 |
|---|---|
| **미확정** | AI가 제안만 했거나 아직 입력되지 않은 상태. 계산에 쓰이지 않음 |
| **확정** | 사용자가 확인하거나 수정(또는 직접 입력)해서 저장된 상태. 계산에 쓰임 |

### 5.1 확인 절차

1. 사용자가 대상 연월을 고릅니다.
2. 아직 확정되지 않은 항목이 있으면 AI가 **업무 매칭**(규칙의 업무 표현이 제목과 다를 때), **기준일 규칙**(4.3), **규칙 정규화**, 규칙 칸이 빈 JOB의 **규칙**을 **근거 원문 문장과 함께** 제시합니다. 화면에는 이 규칙으로 계산한 앞 달·대상 월·다음 달의 기준일 날짜도 미리 보여 줍니다.
3. 사용자가 **확인 / 수정 / 거부** 중 하나를 고릅니다.
   - **확인·수정**: `data/confirmed.json`에 저장되고 확정됩니다. 확정된 규칙은 **모든 달에** 바로 적용됩니다 (예: 자동이체 5일자 응당일 규칙을 확정하면 다른 달을 볼 때 다시 확정할 필요가 없습니다).
   - 기준일·규칙은 **한 번 확정하면 근거가 바뀌기 전까지 다시 묻지 않습니다.** 달을 바꿔도 마찬가지입니다.
   - **거부**: 미확정으로 남고, 직접 입력할 수 있습니다.
4. AI를 쓸 수 없으면 (API 키 없음, 호출 실패, 시간 초과, 응답 형식 오류) 기준일과 규칙을 **화면에서 직접 입력**합니다. 직접 입력해도 AI로 확정한 것과 같은 등록일이 나옵니다.

### 5.2 저장 방식

- 확정값(기준일, JOB 규칙)은 **`data/confirmed.json` 한 파일**에 저장합니다.
- 저장 도중 끊겨도 파일이 깨지지 않도록 **임시 파일에 쓴 뒤 이름을 바꾸는 방식**으로 저장합니다.
- 파일을 읽을 수 없거나(JSON 형식 오류) 내용 형식이 다르면 **모든 값을 미확정**으로 처리합니다.
- 파일이 잠겨 있거나 쓸 수 없으면 `CONFIRM_SAVE_FAILED`를 표시하고 미확정 상태를 유지합니다.
- 저장 도중 끊겨서 남은 임시 파일은 프로그램을 시작할 때 무시하고 정리합니다.
- 테스트는 임시 폴더를 써서 실제 `data/confirmed.json`을 읽거나 쓰지 않습니다.
- **대기 중인 제안**(확정 전)은 `data/pending.json`에 저장합니다. 앱을 닫았다 열어도 같은 근거의 제안은 다시 쓰고 AI를 다시 부르지 않습니다. 확정·거부되거나 근거가 바뀌면 지웁니다. 계산에는 쓰지 않습니다.
- **여러 항목을 한 번에 확정**해도 항목마다 따로 저장합니다. 일부만 저장에 실패하면 그 항목만 `CONFIRM_SAVE_FAILED`로 미확정에 남습니다.

### 5.3 확정이 풀리는 경우 (무효화)

확정값은 **근거가 된 원문이 바뀌면** 미확정으로 돌아가고 다시 확인을 요청합니다. 근거가 그대로면 확정값이 유지되어 다시 계산해도 결과가 같습니다.

| 확정값 | 근거 (이 중 하나라도 바뀌면 무효) |
|---|---|
| 기준일 규칙 | `business-explanation.md`의 해당 업무 절 (달력이 바뀌면 규칙은 그대로 두고 날짜만 다시 계산) |
| JOB 규칙 | `batch-schedule.md`의 해당 JOB 행, 그 JOB이 **참조하는** `business-explanation.md` 업무 절 (예: "자동이체"를 참조하는 B001은 "급여" 절이 바뀌어도 유지) |
| 업무 매칭 | 규칙에 적힌 업무 표현, `business-explanation.md`의 **제목 목록** (제목이 추가·삭제·변경되면 다시 확인) |

- 달력(`business-calendar.md`)을 고쳐도 확정은 풀리지 않습니다. 확정된 규칙으로 날짜만 다시 계산됩니다.
- 비교할 때 **공백과 줄바꿈 차이는 무시**합니다. 줄 끝에 공백을 하나 추가한 것만으로는 확정이 풀리지 않습니다.

## 6. 검증

### 6.1 1단계: 가드레일 (오류 코드)

| 오류 코드 | 조건 | 처리 | 막는 범위 |
|---|---|---|---|
| `FILENAME_FORMAT` | 파일 이름이 `BATCH_SCHEDULE_YYYYMM.xlsx` 형식이 아님 | ⛔ 중단 | 검증 |
| `INVALID_YEAR_MONTH` | 존재할 수 없는 연월 (예: `202613`) | ⛔ 중단 | 검증 |
| `FILE_UNREADABLE` | 빈 파일, xlsx가 아닌 파일(확장자만 바꾼 파일 포함), 읽을 시트 없음 | ⛔ 중단 | 검증 |
| `UNSAFE_CONTENT` | 매크로, 외부 데이터 연결, OLE·포함 개체, 수식이 들어 있음 | ⛔ 중단 | 검증 |
| `FILE_TOO_LARGE` | 10MB 또는 JOB 1,000행 초과 | ⛔ 중단 | 검증 |
| `DATE_COLUMN_MISMATCH` | 날짜 열 개수나 헤더가 그 달 1일~말일과 다름 | ⛔ 중단 | 검증 |
| `INVALID_CELL_VALUE` | 셀에 대문자 `O`나 빈칸이 아닌 값 | ⛔ 중단 | 검증 |
| `DUPLICATE_JOB_ID` | xlsx에 같은 JOB ID가 두 번 이상 | ⛔ 중단 | 검증 |
| `EMPTY_JOB_ID` | xlsx에 JOB ID가 빈 행 | ⛔ 중단 | 검증 |
| `MD_FILE_MISSING` | 필요한 MD 파일이 없음, 빈 파일, 읽을 수 없음 (`business-explanation.md`는 필요할 때만, 3장 참고) | ⛔ 중단 | 매트릭스 + 검증 |
| `MD_SYNTAX_ERROR` | 3개 MD 파일의 문법 오류 (4.5의 거부 예시, 필수 열(JOB ID·수행일 규칙·시작 시각) 없음, `batch-schedule.md`의 JOB ID 중복 포함) | ⛔ 중단 | 매트릭스 + 검증 |
| `START_TIME_INVALID` | 시작 시각이 비어 있거나 형식 오류 (`24:00`, `9:05` 포함) | ⛔ 중단 | 매트릭스 + 검증 |
| `CALENDAR_MISSING` | 계산에 쓰인 달의 달력(`## YYYY-MM`)이 없음. 없는 달을 표시 | ⛔ 중단 | 매트릭스 + 검증 |
| `BASE_DATE_UNCONFIRMED` | 계산에 쓰이는 기준일의 기준일 규칙이 미확정 | ⛔ 중단 | 검증 전체 (매트릭스는 해당 JOB 행만 "미확정") |
| `JOB_RULE_UNCONFIRMED` | JOB 설명으로 판단하는 JOB의 규칙이 미확정 | ⛔ 중단 | 검증 전체 (매트릭스는 해당 JOB 행만 "미확정") |
| `BUSINESS_MATCH_UNCONFIRMED` | 규칙의 업무 표현이 어느 업무 설명 절인지 미확정 (제목과 다르고 아직 확인 안 함, 또는 AI가 찾지 못함) | ⛔ 중단 | 검증 전체 (매트릭스는 해당 JOB 행만 "미확정") |
| `CONFIRM_SAVE_FAILED` | 확정값 파일을 저장할 수 없음 | ⛔ 저장 실패 표시 | 해당 값은 미확정 유지 |
| `JOB_ONLY_IN_FILE` | xlsx에만 있고 규칙에는 없는 JOB | ⚠️ 경고 후 계속 | - |
| `JOB_ONLY_IN_RULES` | 규칙에만 있고 xlsx에는 없는 JOB | ⚠️ 경고 후 계속 | - |

- **중단**: 오류 코드와 내용을 화면에 보여 주고, 막는 범위(매트릭스·검증)를 진행하지 않습니다.
- **경고**: 경고를 표시하고, 나머지 JOB으로 2단계를 진행합니다.
- **잘못된 파일**: 표의 위쪽 9개 코드(`FILENAME_FORMAT` ~ `EMPTY_JOB_ID`)는 xlsx 형식 오류입니다. 이 중 하나라도 해당하면 결과는 **"잘못된 파일입니다"** 이고, 해당하는 사유 코드를 모두 함께 보여 줍니다 (3.5.1).

### 6.2 2단계: 스케줄링 검증

JOB마다 계산한 등록일과 xlsx의 `O`를 날짜별로 비교합니다.

| 판정 | 조건 | 표시 |
|---|---|---|
| **정상** | 계산상 등록일이고 `O` 있음, 또는 계산상 등록일이 아니고 빈칸 | 초록 (`verdict-ok`) |
| **누락** | 계산상 등록일인데 빈칸 | 빨강 (`verdict-missing`) |
| **초과** | `O`가 있는데 계산상 등록일이 아님 | 주황 (`verdict-excess`) |

**한쪽에만 있는 JOB**

| 경우 | 처리 |
|---|---|
| 규칙에만 있는 JOB (`JOB_ONLY_IN_RULES`) | 계산상 등록일을 모두 **누락**으로 판정 (등록을 통째로 빠뜨렸을 가능성) |
| 파일에만 있는 JOB (`JOB_ONLY_IN_FILE`) | 비교할 규칙이 없으므로 **판정에서 빼고** 경고만 표시 |

## 7. 화면 구성

| 화면 | 기능 |
|---|---|
| **등록 일정** | 연월을 고르면 모든 JOB의 등록일을 달력 매트릭스로 표시 (행은 JOB, 열은 1일~말일). 앞 달·다음 달 기준일에서 나온 등록일도 대상 월이면 표시 (예: 12/1 09:00 수행 JOB은 11월 매트릭스 30일 칸, 10월 말일자 응당일 11-02 수행분은 11-01 칸). 미확정 값에 영향받는 JOB 행은 "미확정, 확인 필요"로 표시하고 나머지 JOB은 정상 표시 |
| **기준일·규칙 확인** | AI가 제안한 기준일과 JOB 규칙을 근거 원문 문장과 함께 보여 주고 확인·수정·거부·직접 입력 |
| **검증** | xlsx를 올리면 가드레일 결과(오류 코드)와 정상·누락·초과 매트릭스 표시 |
| **채팅** | 문장으로 질문하면 계산된 등록일 데이터를 근거로 답변 |

### 7.1 채팅

**질문 예시**
- "B001은 12월에 언제 등록돼?" (정답: 2026-12-06)
- "25일에 등록되는 배치는 뭐야?"

**처리 순서**
1. AI가 질문을 조건으로 풉니다. 예: "25일에 등록되는 배치는 뭐야?" → `{JOB: 없음, 월: 2026-11, 일: 25}`
2. 코드가 그 조건으로 계산 결과에서 **정답 목록**(날짜와 JOB ID)을 직접 뽑습니다.
3. AI가 답변 문장과 함께 **인용 목록**(예: `[{날짜: 2026-11-25, JOB: B106}]`)을 만듭니다.
4. 코드가 두 가지를 확인합니다. ① 인용 목록이 정답 목록과 **정확히 같은지**, ② 인용한 날짜와 JOB ID가 **문장 안에 모두 들어 있는지**. 하나라도 어긋나면 답을 버리고 오류를 표시합니다.

**규칙**
- **기준 월**: 질문에 월이 없으면 화면에서 고른 달 기준입니다. 연도 없이 월만 있으면 화면에서 고른 달을 **포함한 12개월**(고른 달 ~ 11개월 뒤) 안에서 찾습니다. (예: 2026-11을 보고 있을 때 "11월" = 2026-11, "12월" = 2026-12, "1월" = 2027-01)
- **조회 범위 안이지만 달력이 없는 달**: 예를 들어 지금 데이터(달력 2027-01까지)에서 "2027년 3월 B001 등록일"을 물으면 `CALENDAR_MISSING`과 없는 달을 보여 줍니다.
- **질문한 달에 오류가 있을 때**: 그 달에 매트릭스를 막는 오류(`MD_FILE_MISSING`, `MD_SYNTAX_ERROR`, `START_TIME_INVALID`, `CALENDAR_MISSING`)가 있으면 답 대신 그 오류 코드를 보여 줍니다.
- **미확정 JOB**: 정답 목록에서 빼고 답합니다.
- **조건으로 풀 수 없는 질문**: "이 질문은 답할 수 없어요"를 표시합니다.
- **범위 밖 질문 (추론 금지)**: 배치 작업 등록 일정과 관련 없는 질문은 AI가 답을 추론하거나 지어내지 않고, 정해진 문장 **"배치 작업 등록 일정 범위 밖의 내용이라 알 수 없어요."** 만 표시합니다.
  - 범위 안: 등록일·수행일, 수행일 규칙, 업무 기준 설명 문서에 적힌 내용, 영업일 달력, 검증 결과
  - 범위 밖 예시: 날씨·일반 상식, 업무 설명 문서에 **없는** 업무 정보(예: "자동이체 출금 수수료는 얼마야?"), 배치의 실제 수행 결과
  - AI는 질문을 조건으로 풀 때 "범위 밖"으로 분류만 하고, 답변 문장은 만들지 않습니다. 업무 문서 검색(RAG)에서 근거를 찾지 못한 업무 질문도 범위 밖으로 처리합니다.
  - 배치 실행·외부 사이트 등록 같은 **작업 요청**은 "이 서비스에서는 할 수 없는 작업이에요"로 거절합니다.

### 7.2 채팅 가드레일

| 가드레일 | 조건 | 처리 | 안내 문장 / 코드 |
|---|---|---|---|
| **개인정보·민감정보** | 질문이나 MD 파일에 주민등록번호, 계좌번호, 카드번호, 전화번호 형태의 값이 있음 | AI·로그·트레이스로 보내기 **전에 가림**(`******`). 질문 자체가 개인정보를 묻거나 다루는 요청이면 **거부** | `PII_MASKED` (경고) / "개인정보는 다루지 않아요." |
| **업무와 무관한 질문** | 날씨·일반 상식 등 배치 일정과 관계없는 질문 | AI 추론 없이 고정 문장 (7.1 범위 밖 질문과 같음) | "배치 작업 등록 일정 범위 밖의 내용이라 알 수 없어요." |
| **조회 범위 제한** | 질문 대상 달이 화면에서 고른 달 기준 **앞 1개월 ~ 뒤 11개월** 밖 (예: 2026-11을 보고 있을 때 2026-09 이전, 2027-11 이후) | 계산하지 않고 안내 | `OUT_OF_RANGE_MONTH` / "조회할 수 있는 범위(2026-10 ~ 2027-10)를 벗어났어요." |
| **입력 크기 제한** | 채팅 입력이 **500자** 초과 (500자는 처리, 501자부터 거부) | 처리하지 않고 안내 | `INPUT_TOO_LONG` / "질문은 500자 이내로 입력해 주세요." |
| **요청 횟수 제한** | 최근 60초 동안 **10회** 초과 (10번째까지 처리, 11번째부터 거부) | 잠시 차단 | `RATE_LIMITED` / "요청이 많아요. 잠시 후 다시 시도해 주세요." |
| **데이터 변경 방지** | 채팅으로 MD 파일이나 확정값(`confirmed.json`)을 바꾸거나 지우거나 확정하려는 요청 | 거부. 데이터는 파일 편집과 확인 화면에서만 바뀜 | "채팅으로는 데이터를 바꿀 수 없어요. 확인 화면이나 MD 파일에서 수정해 주세요." |

- 입력 크기·횟수·개인정보 검사는 **AI를 호출하기 전에 코드로** 합니다.
- 개인정보 형태 (정규식 기준): 주민등록번호 `\d{6}-?[1-4]\d{6}`, 카드번호 `\d{4}-?\d{4}-?\d{4}-?\d{4}`, 전화번호 `01\d-?\d{3,4}-?\d{4}`, 계좌번호 하이픈 포함 10~14자리 숫자
- **AI 미설정**: "AI 미설정으로 채팅을 사용할 수 없음"을 표시합니다.
