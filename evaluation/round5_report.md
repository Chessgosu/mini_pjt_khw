## 분석·개선

### 4차 결과 (20/20, RAGAS 일부 누락)

- 4차에서 RAGAS 측정값 40개 중 13개가 시간 초과로 빠졌고, 모범 답안을 쓴 뒤에도 #1·#2의 context_precision이 0.0이었습니다.
- 원인 확인: RAGAS context_precision은 근거(context)를 하나씩 따로 보여 주고 "이 근거가 답에 도달하는 데 쓰였나"를 판정합니다. 채팅이 등록일 한 건마다 근거를 따로 만들어서 근거 하나만으로는 답 전체(예: B006의 11-01과 11-29)를 설명할 수 없었고, 채점 AI가 모두 "쓰이지 않음"으로 판정했습니다. (B006 판정 이유 예: "11-01 정보는 있지만 답의 11-29가 이 근거에 없음")

| 개선 | 내용 |
|---|---|
| 근거 묶기 | 도구 호출 한 번의 결과를 근거 문서 하나로 (JOB 질문: 그 달 등록일 전부 + 근거 + 등록일 규칙, 날짜 질문: 그날 JOB 전부). 수정 후 B006·25일 판정이 모두 '쓰임'(verdict=1)으로 바뀌는 것을 개별 확인 |
| 검증된 인용 목록 반환 | `ask()` 결과에 `citations`(정답 목록과 대조를 통과한 인용) 추가 |
| RAGAS 누락 방지 | 동시 호출 4→2, 제한 시간 180→300초. 측정값이 하나라도 빠지면 보고서를 만들지 않고, 채팅 결과만 저장해 `--ragas-only`로 RAGAS만 다시 잼 |

- RAGAS 채점 기준·채점 모델은 바꾸지 않았습니다.

### 5차 첫 실행 (20/20, RAGAS 1건 누락) → 재실행

- 첫 실행에서 #5 faithfulness 1건이 빠졌고, `--ragas-only` 재측정도 같은 곳에서 실패했습니다 (한도 문제 아님, 재현됨).
- 원인: 근거 문장의 규칙을 작은따옴표로 감쌌는데(`기준일 규칙 '첫 영업일, …'`), 채점 AI가 판정 이유에 이를 인용하며 `\'`로 써서 RAGAS가 응답 JSON을 읽지 못했습니다.
- 수정: 근거 문장의 규칙 인용 기호를 `「…」`로 변경 (`src/chat.py` 기준일 근거, `src/tools.py` 수행일 규칙 근거). 채점 기준·채점 모델·RAGAS 코드는 그대로이며, 채팅부터 전체를 다시 실행한 결과가 이 보고서입니다.
